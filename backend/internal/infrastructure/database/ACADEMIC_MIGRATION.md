# Разрешение дубликатов активных попыток экзамена

При обновлении PostgreSQL миграция создаёт partial unique index
`idx_exam_attempt_one_in_progress`: у одного студента может быть только одна
попытка со статусом `in_progress` для одного экзамена.

Миграция сама закрывает только попытки, у которых зафиксированный серверный
`expires_at` закончился больше минуты назад. Если для одной пары
`exam_id`/`student_id` остаётся несколько действующих `in_progress`, она
останавливается с ошибкой и не выбирает попытку-победителя.

## Процедура

1. Сохраните резервную копию и выполните диагностический запрос:

   ```sql
   SELECT exam_id, student_id, id, started_at, expires_at, created_at
   FROM exam_attempts
   WHERE status = 'in_progress'
   ORDER BY exam_id, student_id, started_at, created_at, id;
   ```

2. Для каждой конфликтной пары преподаватель или ответственный за учебный
   процесс выбирает попытку, которую студент действительно продолжает. Все
   строки сохраняются: история попыток не удаляется.

3. В согласованное окно обслуживания явно измените статус только выбранных
   ответственным лицом не продолжаемых попыток на `expired` и зафиксируйте
   причину во внешнем журнале изменений организации. Не применяйте массовый
   запрос по времени или ID без такого решения.

4. Повторно запустите `RunMigrations`. После отсутствия конфликтов индекс
   создастся; повторный запуск миграции безопасен.

Миграция не должна обходиться отключением индекса: это снова позволит
параллельным запросам создать несколько активных попыток.
